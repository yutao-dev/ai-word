# AI Skill 架构设计方案

## 1. 项目背景

当前 AI 工作流在执行多轮迭代时，每轮都会发送完整的系统提示词（约 2500 tokens），导致 Token 重复计费。为了解决这个问题，我们提出了基于 AI Skill 概念的架构设计，通过模块化的文档管理和 LLM 缓存机制，实现 Token 消耗的优化。

## 2. 核心概念

### 2.1 AI Skill 定义

AI Skill 是一种模块化的能力单元，通过文档形式封装特定领域的知识和指令，为 AI 模型提供专业化的指导。

### 2.2 设计理念

- **模块化**：将不同领域的知识分离为独立的 Skill 文档
- **智能化**：根据用户请求自动选择相关 Skill
- **高效性**：利用 LLM 缓存机制减少 Token 消耗
- **可配置性**：用户可控制是否启用特定 Skill

## 3. 架构设计

### 3.1 系统架构

```
┌─────────────────────┐      ┌─────────────────────┐
│                     │      │                     │
│  用户请求处理层      │─────>│  Skill 分析与选择    │
│                     │      │                     │
└─────────────────────┘      └─────────────────────┘
                                      │
                                      ▼
┌─────────────────────┐      ┌─────────────────────┐
│                     │<─────│  文档管理模块        │
│  AI 工作流执行层     │      │                     │
│                     │      └─────────────────────┘
└─────────────────────┘              │
        │                            │
        ▼                            ▼
┌─────────────────────┐      ┌─────────────────────┐
│                     │      │                     │
│  LLM 服务层         │<─────│  缓存管理模块        │
│                     │      │                     │
└─────────────────────┘      └─────────────────────┘
```

### 3.2 核心组件

#### 3.2.1 Skill 分析与选择模块

- **功能**：分析用户请求，识别所需的 Skill
- **实现**：使用轻量级分类模型或规则引擎
- **输出**：选择的 Skill 列表（包含核心文档和领域文档）

#### 3.2.2 文档管理模块

- **功能**：管理 Skill 文档的存储和检索
- **文档类型**：
  - 核心文档（MCP Functions）
  - 领域文档（如文档编辑、信息提取等）
  - 精简版文档（对应每个文档的精简版本）
- **存储结构**：
  ```
  skills/
  ├── core/
  │   ├── mcp_functions.md
  │   └── mcp_functions_compact.md
  ├── document_editing/
  │   ├── document_editing.md
  │   └── document_editing_compact.md
  └── information_extraction/
      ├── information_extraction.md
      └── information_extraction_compact.md
  ```

#### 3.2.3 缓存管理模块

- **功能**：管理 LLM 缓存策略
- **策略**：
  - 首轮：发送完整文档
  - 后续轮次：发送精简文档
  - 兜底：无精简文档时使用完整文档
- **缓存键设计**：基于 Skill 类型和版本

#### 3.2.4 AI 工作流执行层

- **功能**：执行工作流，调用 LLM 和 MCP 函数
- **流程**：
  1. 接收用户请求
  2. 分析并选择 Skill
  3. 加载对应文档
  4. 执行多轮迭代
  5. 处理 LLM 响应
  6. 调用 MCP 函数
  7. 返回结果

## 4. 执行流程

### 4.1 首轮执行流程

1. **用户请求分析**：分析用户问题，确定所需 Skill
2. **文档加载**：
   - 必加载：核心文档（MCP Functions）
   - 可选加载：相关领域文档
3. **提示词构建**：将加载的完整文档拼接为系统提示词
4. **LLM 调用**：发送完整系统提示词和用户请求
5. **缓存建立**：LLM 缓存系统提示词
6. **响应处理**：解析 LLM 响应，执行相应操作

### 4.2 后续轮次执行流程

1. **上下文分析**：分析当前工作流状态和对话历史
2. **文档加载**：
   - 必加载：核心文档（精简版）
   - 可选加载：相关领域文档（精简版）
3. **提示词构建**：将加载的精简文档拼接为系统提示词
4. **LLM 调用**：发送精简系统提示词和对话历史
5. **缓存命中**：LLM 利用缓存的完整系统提示词
6. **响应处理**：解析 LLM 响应，执行相应操作

## 5. 技术实现要点

### 5.1 文档结构设计

#### 5.1.1 核心文档（MCP Functions）

**完整版**：
- 包含所有 MCP 函数的详细说明
- 执行策略和最佳实践
- 响应格式定义

**精简版**：
- 函数名称列表
- 核心执行规则
- 响应格式模板

#### 5.1.2 领域文档

**完整版**：
- 领域特定知识
- 专业术语解释
- 领域最佳实践
- 示例和案例

**精简版**：
- 领域核心概念
- 关键指令
- 简要示例

### 5.2 缓存策略

- **缓存键**：`{skill_type}_{skill_version}_{model_name}`
- **缓存有效期**：遵循 LLM 厂商的缓存策略（通常 5-30 分钟）
- **缓存预热**：系统启动时预加载常用 Skill 文档
- **缓存监控**：跟踪缓存命中率和效果

### 5.3 错误处理

- **文档加载失败**：使用默认文档
- **Skill 分析失败**：使用核心文档
- **缓存未命中**：使用完整版文档
- **LLM 响应错误**：重试或切换模型

## 6. 优势分析

### 6.1 技术优势

- **Token 消耗优化**：通过精简文档和缓存机制，减少约 28% 的 Token 消耗
- **系统可扩展性**：模块化设计便于添加新的 Skill
- **性能提升**：缓存机制减少了 LLM 处理时间
- **维护成本降低**：文档驱动设计便于知识更新

### 6.2 商业优势

- **成本节约**：减少 Token 消耗直接降低 API 调用成本
- **功能丰富**：通过领域 Skill 提供更专业的能力
- **用户体验**：根据具体任务提供最相关的指导
- **竞争优势**：创新的架构设计提升系统竞争力

### 6.3 用户优势

- **可配置性**：用户可控制是否启用 Skill
- **响应速度**：缓存机制提高响应速度
- **专业性**：领域 Skill 提供更专业的指导
- **稳定性**：兜底机制确保系统稳定运行

## 8. 风险评估

### 8.1 潜在风险

- **文档管理复杂度**：需要建立完善的文档版本控制
- **缓存一致性**：确保不同 Skill 文档之间的缓存状态一致
- **冷启动问题**：首次使用新 Skill 时 Token 消耗较高
- **分类准确性**：Skill 分析模型的准确性影响系统效果

### 8.2 风险缓解

- **文档管理系统**：实现版本控制和自动化测试
- **缓存策略优化**：设计合理的缓存键和预热机制
- **渐进式部署**：先在非关键场景测试
- **持续学习**：基于用户反馈优化分类模型

## 9. 技术栈建议

- **后端**：FastAPI, Python
- **文档管理**：Markdown, YAML
- **缓存**：Redis (可选，用于本地缓存)
- **分类模型**：轻量级 NLP 模型或规则引擎
- **部署**：Docker, Kubernetes

## 10. 结论

AI Skill 架构设计是一种创新的解决方案，通过模块化的文档管理和 LLM 缓存机制，实现了 Token 消耗的优化和系统能力的扩展。这种设计不仅解决了当前的成本问题，还为未来的功能扩展和性能优化奠定了基础。

通过渐进式的实施计划，可以在保证系统稳定性的同时，逐步实现架构的完整功能，为用户提供更专业、更高效的 AI 服务。
